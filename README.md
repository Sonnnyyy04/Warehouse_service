# Warehouse Service

Backend проекта для автоматизации складского учета через мобильное приложение.

Сервис хранит складские сущности, обрабатывает QR-маркеры, поддерживает приемку товара по Excel, поиск товара на складе, перемещение коробов/партий, отгрузку и историю складских операций.

## Возможности

- Авторизация пользователей по логину и паролю.
- Роли пользователей: администратор и работник склада.
- Управление сотрудниками.
- Управление товарами, стеллажами, ячейками, коробами и партиями.
- Импорт поставок из Excel.
- Сопоставление товаров поставщика с внутренней номенклатурой.
- Генерация QR-маркеров и PDF с QR-наклейками.
- Сканирование QR-кодов и получение карточки складского объекта.
- Поиск товара на складе с подбором коробов для отбора.
- Перемещение коробов и партий с проверкой складских ограничений.
- Отгрузка товара с исключением коробов из активного остатка.
- Журналирование сканирований и складских операций.

## Ключевые складские правила

- Товар создается с начальным количеством и должен быть связан с коробом.
- Короб может быть размещен только в активной ячейке.
- Ячейка хранит один тип товара.
- Короб не должен смешивать разные товары.
- Отгруженные короба не участвуют в активном остатке.
- История операций сохраняется для аудита действий пользователей.

## Приемка товара

Флоу приемки:

1. Администратор загружает Excel-накладную.
2. Backend разбирает строки файла.
3. Позиции автоматически сопоставляются с товарами по алиасам поставщика.
4. Несопоставленные позиции администратор связывает вручную или создает новый товар.
5. После сопоставления всех строк backend формирует партии, короба и QR-маркеры.
6. Администратор скачивает PDF с QR-наклейками и печатает их для расклейки на короба.

## QR-маркировка

QR-маркер связывает физический объект склада с записью в базе данных.

Поддерживаемые объекты:

- товар;
- стеллаж;
- ячейка;
- короб;
- партия.

При сканировании backend определяет тип объекта, возвращает карточку объекта и записывает событие сканирования.

```bash
docker-compose run --rm migrate
```

## Деплой

Деплой выполняется через GitHub Actions.

Workflow:

```text
.github/workflows/backend-ci-cd.yml
```

На push в `main` workflow:

1. запускает `go test ./...`;
2. подключается к VPS по SSH;
3. загружает файлы проекта на сервер;
4. пересобирает Docker-контейнеры;
5. запускает миграции;
6. перезапускает API;
7. очищает легкий Docker-мусор без удаления PostgreSQL volume.

Подробности деплоя описаны в `DEPLOYMENT.md`.
